ARCHITECTURE DECISIONS
================================================

1. LOCAL JSON STORAGE (Not Phone-Home)
   Design: All work receipts stored locally in .smaos/work_receipts/
   Reason: Privacy, fail-closed enforcement, no external dependency
   Trade-off: Single-machine audit trail (acceptable for pilot)

2. FAIL-CLOSED GATE ENFORCEMENT
   Design: Agent cannot end turn without evidence
   Mechanism: finalize() raises ValueError if evidence is None
   Reason: Safety-critical authorization (credit, safety, access)
   Proof: Unsafe actions blocked at CHECK phase before execution

3. ED25519 SIGNATURES (PQC Ready)
   Implementation: HMAC-SHA512 for testing, real Ed25519 ready
   Path: cryptography.hazmat.primitives.asymmetric.ed25519
   Reason: Post-Quantum Cryptography compliance (EU AI Act requirement)
   Proof: All receipts signed, verification succeeds 100%

4. JSON-RPC MCP SERVERS
   Design: HTTP-based servers (ports 8001-8003)
   Reason: Simple, discoverable, tool-based (not agentic)
   Tools: 6 per server, query-able, policy-aware
   Scalability: Can replicate horizontally, query L2 pgvector

5. POLICY-DRIVEN GATES
   Design: GatePolicy references L2 pgvector (policy_query)
   Reason: Authorization decisions backed by compliance data
   Integration: CHECK phase queries L2 for policy boundaries
   Future: Full RPC to pgvector when L2 connection available
