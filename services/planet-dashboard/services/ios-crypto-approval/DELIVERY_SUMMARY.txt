================================================================================
FLOW ARCHITECTURE
================================================================================

Step 1: SECURE ENCLAVE KEY GENERATION
  - Uses SecureEnclave.P256.PrivateKey (hardware-backed)
  - Private key never leaves the Secure Enclave
  - Public key exported as PEM for server-side verification

Step 2: USER APPROVAL PROMPT
  - iOS Shortcut displays: "Approve this decision?"
  - User selects YES or NO
  - Abort if NO

Step 3: FaceID AUTHENTICATION (LAContext)
  - Biometric gate: requires FaceID or fallback auth
  - System prompt: "Approve this decision with biometric authentication"
  - Abort if authentication fails

Step 4: CAPSULE HASHING (SHA256)
  - Hash the decision content
  - Output: 256-bit digest (base64-encoded)

Step 5: P256 SIGNING (ECDSA)
  - Sign the capsule hash with Secure Enclave private key
  - Algorithm: ECDSA-P256 (NIST P-256, FIPS 186-4)
  - Output: ECDSA signature (base64-encoded)

Step 6: VISION API SUBMISSION (HTTP POST)
  - Endpoint: https://api.vision.example.com/v1/govern
  - Method: POST
  - Content-Type: application/json
  - Authorization: Bearer {token}
  
  Payload:
  {
    "capsule_hash": "mnSTy7B7+DBQVfnwUQYBkLadWVmvKaQ83hqU9ds/3FE=",
    "signature": "MEUCIQCVORLPl54Gm3TQ5ZfyoJ4mHZgbf3zGyjxl/cnLZa95sAIgPQU7GECBCo0e...",
    "public_key": "-----BEGIN PUBLIC KEY-----\nMFkwEwYHKoZIzj0CAQYIKoZIzj0DAQcDQgAE...",
    "timestamp": "2026-06-04T01:21:20.588735+00:00",
    "algorithm": "ECDSA-P256"
  }

Step 7: VERIFICATION & RESPONSE
  - Server verifies ECDSA signature using public key
  - Returns approval_id + verified status
  - Client records approval in audit log
